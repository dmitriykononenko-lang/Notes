# Подготовка к публикации в amoМаркете

Чек-лист готовности виджета «Шаблоны задач» к публикации в amoМаркете.
Статусы: ✅ готово в репозитории · 🟡 нужно сделать на стороне аккаунта/юрлица ·
⚠️ риск модерации — учесть.

## 1. Код и манифест (✅ — со стороны разработки готово)

- ✅ `manifest.json`: name/description/short_description через i18n, version
  (поднимать при каждом обновлении!), interface_version 2, locale ru/en,
  support.link + support.email, locations, settings.
- ✅ Локализация ru/en (`widget/i18n/`), без «голых» ключей в интерфейсе.
- ✅ Колбэки `init/render/bind_actions/settings/onSave/destroy` присутствуют.
- ✅ Внешних запросов нет — только same-origin `/api/v4/...` (API amoCRM).
- ✅ Нет `eval`, внешних `<script>`, сторонних доменов.
- ✅ Логотипы: `logo.png` 130×100, `logo_small.png` 108×108, `logo_main.png`
  400×272, полный набор `images/`.
- ✅ Автотесты: `node test/run-tests.js` — 179 проверок зелёные.
- ✅ Пред-полётный валидатор `python3 scripts/validate.py` (размеры логотипов,
  i18n-паритет ru/en, отсутствие `console.*`, manifest в корне, чистота файлов)
  и чистая сборка `bash scripts/package.sh` (валидация → zip без мусора).
- ✅ **Спека (сверено со скилом amocrm-widget / офиц. доки):**
  `installation: true` (булево; на строку `"y"` кабинет отвечает «"installation" field must be TRUE or FALSE only» — проверено 16.09.2026 на приватной карточке koagency), `interface_version: 2`, все 5
  логотипов точных размеров (84×84 / 240×84 / 130×100 / 400×272 / 108×108,
  каждый ≤300 КБ), локации валидные, тип поля настроек `text` (из
  разрешённого набора text/pass/users/users_lp/custom).
- ✅ **Маркетплейс-поля НЕ в манифесте.** Проверено 16.09.2026: карточка
  **приватной** интеграции отвергает их так же, как публичный кабинет
  («Unknown field(s) "free", "countries", "category"»). Поля `free`, `countries`, `category`, а также `code`/`secret_key`
  в `manifest.json` **запрещены** — кабинет отклоняет публичный виджет с
  «Unknown field(s)». Эти параметры (платно/бесплатно, страны, категория) и
  привязка OAuth задаются **в форме кабинета разработчика**, а не в манифесте.
  Валидатор `scripts/validate.py` теперь ошибается, если эти поля вернутся в
  манифест.

## 1b. Приватная vs публичная публикация — развилка (решить ДО сабмита)

Ключевой факт из сверенного скила: **статический валидатор публичного
amoМаркета банит глобаль `AMOCRM.*`** (плюс `console.*`, `confirm(`, `alert(`).

- **Наш виджет читает `AMOCRM.*` в 5 местах** (типы задач, аккаунт, менеджеры,
  текущий пользователь, текущая карточка). `scripts/validate.py` это показывает
  предупреждением.
- **Приватная публикация** (zip на карточке интеграции в аккаунте, через чат
  техподдержки): `AMOCRM.*` **разрешён**, статического валидатора и модерации
  нет. → Как есть, виджет готов **только к этому пути**.
- **Публичный маркетплейс** (листинг, OAuth, модерация): пришлось бы вынести
  все 5 чтений на **бэкенд-bootstrap** (`GET /api/amo/bootstrap` → account,
  users, task_types и т.д.) и заменить прямые вызовы. Это заметная переделка,
  требует своего сервера и OAuth-обвязки.

Пока не выбран публичный путь — держим приватную сборку; переделку под бэкенд
начинаем только по явному решению.

## 1a. Нативные входы (флаг `yp_native_ui`)

По решению владельца в сборке (с v1.1.4) **нативные входы включены**: пункт
«Шаблоны задач» в переключателе типа сообщения, пункт «Редактор шаблонов» в
меню «…» раздела Задачи, локация `everywhere`. Это удобнее, но это зона риска
модерации (модификация родного UI amoCRM).

Для **moderation-safe** варианта код выключается флагом: установить
`NATIVE_UI_DEFAULT = false` в `widget/script.js` (или передать
`yp_native_ui: false`). Тогда останется только официальное ядро: блок в
карточке с красной плашкой (caption-класс), окно выбора, редактор, настройки,
постановка задач, кастомные типы. Тест 19 покрывает выключенный режим.

Если модерация сделает замечание по нативным входам — переключаем флаг и
подаём заново.

## 4. Юридическое (🟡 — обязательно для публичной публикации)

- 🟡 **Политика конфиденциальности** — нужна публичная ссылка. Шаблон:
  `docs/privacy-policy.md` (заполнить реквизиты KO:AGENCY и разместить по
  публичному URL).
- ✅ **Оферта** — шаблон `docs/offer.md` (ИП Кононенко Е.В.); разместить по
  публичному URL и указать в форме.
- ✅ **Модель: платный, за аккаунт, пакеты предоплаты + триал 14 дней:**
  3 мес — **1490 ₽**, 6 мес — **2490 ₽** (+1 в подарок), 12 мес — **3990 ₽**
  (+2 в подарок). Дешевле конкурента в ~2–3 раза на каждом уровне (эфф. ~497/
  356/285 ₽/мес против 1317/921/765). Цена задаётся в форме amoМаркета (в коде/
  манифесте не хранится).
- ✅ **Оплата — через биллинг amoМаркета**, в виджете код оплаты не нужен.
  Доступ по подписке enforce'ит amoCRM; самопроверку подписки в коде решено
  не добавлять.
- 🟡 Реквизиты для выплат + договор разработчика amoCRM — заполнить/подписать
  на стороне ИП при отправке на публикацию.
- 🟡 **Технический аккаунт** для публичной интеграции: бесплатный, действует
  3 месяца, один на интеграцию (требование маркетплейса).
- ℹ️ Модерация обычно **1–2 рабочих дня** (код-аудит + функциональный тест
  установки/удаления командой маркета).
- ⚠️ Локация `everywhere` (для пунктов в переключателе/меню Задач) по офиц.
  докам «замедляет приложение» — держим осознанно; при замечании модерации
  переключаем во moderation-safe (`yp_native_ui: false`).

## 5. OAuth / интеграция (🟡 — на стороне аккаунта)

- Виджет работает на сессии браузера + JS API + same-origin REST, своего
  бэкенда нет. Для публичной интеграции amoCRM всё равно попросит заполнить в
  карточке интеграции: **Ссылку для перенаправления** (redirect_uri — можно
  страницу сайта KO:AGENCY), при желании хук об отключении, доступы.
- Секрет/ключи (если потребуются) — выдаются в карточке интеграции; в код
  виджета их вшивать не нужно.
- ⚠️ **Если публикация идёт через «amoМаркет → Моё приложение»** (публичная
  интеграция, отдельная от приватной): у неё **свой `code`** (задаётся вручную,
  **неизменяем**) и **`secret_key`** (генерируется **один раз**, показывается
  единожды). Тогда:
  - создать публичное приложение, задать `code`, сгенерировать секрет;
  - **синхронно** вписать одно и то же значение в `manifest.widget.code` /
    `manifest.widget.secret_key` (в архиве), пересобрать (`package.sh`, поднять
    версию);
  - секрет читать **точно из буфера/DOM**, не со скриншота (l/I/1, O/0);
  - не перегенерировать ключ после сборки (иначе рассинхрон архив↔кабинет).
  Если же публикуете **приватную интеграцию через чат техподдержки** (наш
  текущий путь) — `code`/`secret_key` в манифесте не требуются.

## 6. Процесс сабмита (🟡 — выполняет владелец аккаунта-разработчика)

1. Настройки → Интеграции → ваша интеграция «Шаблоны задач» (приватная).
2. Залить актуальный `task-templates.zip` (текущая версия — см. manifest).
3. Заполнить вкладку публикации: название, описания (`docs/amomarket.md`),
   логотип/скриншоты, ссылку на политику конфиденциальности, поддержку,
   тариф.
4. Отправить на модерацию. По замечаниям — правим, поднимаем версию, заливаем
   заново.

## 7. Перед каждым релизом (короткий ритуал)

- `node test/run-tests.js` — зелёный.
- Поднять `version` в `manifest.json` (иначе amoCRM отдаёт старый кэш).
- `bash scripts/package.sh` — пред-полётная проверка + чистая сборка архива.
- Проверить на тестовом аккаунте, затем сабмит.
